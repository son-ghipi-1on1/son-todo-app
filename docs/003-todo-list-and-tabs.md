# 003: 一覧表示・タブ切替

## 概要

トップページ(`/`)にTodo一覧を表示し、「未完了」「完了済み」タブで切り替えられるようにする。本チケットはこのアプリの土台となる画面で、以降のチケット(作成・トグル・編集・削除・並び替え)はすべてこの一覧の上に機能を追加していく。

## 関連要件

- F-02(タスク一覧表示)
- F-08(完了タスクの切替表示)
- 7.1節(画面構成)、7.3節(状態別の表示)

## 依存

- 002

## 見積

1.5〜2時間

## タスク

- [ ] `app/page.tsx`(Server Component)でSupabaseから `todos` を取得する
- [ ] `app/components/TodoList.tsx` / `TodoItem.tsx`(表示専用、チェックボックス・タイトル・期限日を表示)を作成する
- [ ] `app/components/TabSwitcher.tsx`(Client Component)で「未完了」「完了済み」を切り替える
- [ ] 各タブに件数バッジを表示する
- [ ] デフォルトは「未完了」タブ、並び順は「期限が近い順」(`due_date ASC NULLS LAST, created_at DESC`)
- [ ] タスクが0件の場合の空状態メッセージを未完了/完了済みそれぞれで出し分ける(7.3節)
- [ ] 読み込み中のスケルトンUIを実装する(`app/loading.tsx` または `<Suspense>`)
- [ ] 通信エラー時のエラーメッセージ + 再試行ボタンを実装する(`app/error.tsx`)

## 実装メモ

- 一覧取得はServer Componentから直接Supabaseを呼び出す。クエリは `lib/supabase.ts` に関数として集約し、`page.tsx` に直書きしない(`CLAUDE.md` の「データ取得」節)。
- `TabSwitcher` はインタラクション(クリックでタブ切り替え)のみ `'use client'` にし、一覧そのものの取得・表示ロジックまでクライアント化しない。
- `error.tsx` は `'use client'` 必須のClient Componentであることに注意(`CLAUDE.md` の「エラー・ローディングUI」節)。
- 並び替えのソート条件そのものは008で選択式にするが、本チケットではデフォルトの「期限が近い順」のみ実装すればよい。

## 完了条件

- `/` にアクセスすると未完了タブがデフォルトで表示され、期限が近い順に並んでいる
- 未完了/完了済みタブを切り替えると該当するタスクのみ表示され、件数バッジが正しい
- 未完了0件・完了済み0件それぞれで異なる空状態メッセージが出る
- 意図的にSupabase接続を失敗させるとエラーメッセージと再試行ボタンが表示される
